# 剣の接触判定と現行の照準レイ入力の課題（Quest向け戦闘要件への影響）

状態：**技術検討（未実装）**。Quest戦闘の実装に着手する前に、入力の境界を見直す必要があるため先に報告する。
対象要件：仕様書ドラフトの **E2**（Editorで剣の接触を代替して再現）と **Q-2**（コントローラを剣として振り、その一振り中に敵の体に触れた場合だけ命中。空振り・触れ続けでは余分に数えない）。

## 1. 現行設計（9月28日に作った骨格）

```csharp
public interface IInputController
{
    Ray AimRay { get; }                              // 照準レイ
    bool TryConsumeAttack(out AttackInput attack);  // 「今攻撃した」という瞬間のイベント
}
```

想定していた命中判定は「攻撃の瞬間に照準レイを飛ばし、敵のコライダーに当たれば命中」。Editorでは左クリックがこれにあたる。

## 2. 要件との差

| # | 観点 | 照準レイ（現行） | 剣の接触（Q-2 の要求） | 影響 |
| --- | --- | --- | --- | --- |
| 1 | 時間 | 1フレームの瞬間 | 0.2〜0.5秒の振りの軌跡 | 毎フレームの剣の姿勢（位置＋向き）が必要 |
| 2 | 形 | 太さ0・長さ無限の線 | 手元から約0.9mの刃（線分／カプセル） | 遠くの敵にも当たってしまう。「近づいて斬る」が表現できない |
| 3 | 命中を決めるもの | 入力（クリック・トリガー）が決める | 刃と敵の体の幾何的な接触が決める | 入力層は「攻撃した」ではなく「剣がどこにあるか」だけを渡すべき |
| 4 | 振りの判定 | ボタン | 刃先の速度 | ゆっくり押し当てた・触れたままを命中にしない判定が要る |
| 5 | 1振り1命中 | 1クリック＝1回なので自然に成立 | 1振りの間に何フレームも接触し得る | 振りの開始・終了の区切りと、振りごとの「命中済み」の記録が要る |
| 6 | すり抜け | 起きない | 刃先は最大5〜10m/s。72〜90Hzでは1フレームに6〜14cm進み、薄い部位を飛び越える | 前フレームと今フレームの刃の間を掃引して判定する必要がある |
| 7 | 追跡の乱れ | 影響小 | コントローラの追跡が途切れ・復帰した瞬間に位置が飛び、高速な「振り」と誤判定され得る | 追跡が無効なサンプルや、不自然な移動量の飛びを捨てる |
| 8 | Editor代替 | クリックでそのまま再現 | クリックでは振りを再現できない | マウスのドラッグから刃の姿勢を作り、同じ判定ロジックに流す |

**結論**：現行の `IInputController` は Quest の剣には使えない。このまま旧WBS 4（攻撃・命中判定）を照準レイで作ると、Quest実機の段階で入力・命中判定・Editor代替操作を作り直すことになる。

## 3. 提案する設計

入力を「指す・選ぶ」と「剣」の2つに分ける。

```
【指す・選ぶ】 IPointerInput（現 IInputController を改名・役割を限定）
    Editor: マウス / iPhone: 画面タップ（S2の配置） / Quest: レイ（メニュー操作）
    → 戦闘の命中判定には使わない

【剣】 ISwordPoseSource（新設）
    bool TryGetBladePose(out BladePose pose)   // 手元・刃先の位置、時刻、追跡が有効か
    Quest: コントローラのグリップ姿勢＋刃の長さ・角度のオフセット
    Editor: マウスドラッグから刃の姿勢を作る代替操作
    iPhone: 対象外（S1〜S5では剣操作をしない）
```

判定ロジックは端末に依存させない。

| 部品 | 層 | 役割 | テスト |
| --- | --- | --- | --- |
| `SwingDetector` | Core（純C#） | 刃先の速さと追跡の有無の時系列から「振り開始／振り中／振り終了」を判定。ヒステリシスと最短時間を持たせ、ゆっくりした接触や追跡の飛びを振りと見なさない | `dotnet test` で可能 |
| `SwingHitRegistry` | Core（純C#） | 振りごとに「命中済みの敵」を記録し、同じ振りでの2回目以降の接触を無視（1振り1命中） | `dotnet test` で可能 |
| `SwordHitDetector` | Gameplay | 毎フレーム、前フレームの刃と今フレームの刃の間を補間しながらカプセルで重なり判定（敵の当たり判定レイヤーのみ）→ 振り中かつ未命中なら `Health.ApplyDamage(1)` | Editor で確認 |
| `EditorSwordEmulator` | Platform/EditorSim | カメラ前方約0.5mを手元とし、マウスの移動量で刃を回す。ドラッグの速さがそのまま刃先の速さになる | Editor で確認 |
| `QuestSwordPoseSource` | Platform/Quest | コントローラ姿勢から刃を作る | 11月18日以降に実機 |

初期値（すべて**仮**。Quest実機で調整する）：刃の長さ 0.9m、振り開始 刃先 1.5m/s 以上、振り終了 0.6m/s 未満が 80ms 続いたとき、最短の振り 100ms、敵HP 10・1命中1ダメージ（Q-4 の「約10回」）。

物理エンジンのトリガー（`OnTriggerEnter`）だけに頼らないのは、(1) 高速な刃のすり抜け、(2) 1振り1命中の区切りを自前で持つ必要がある、の2点のため。

## 4. 見積りと計画への影響

| 作業 | 照準レイ版（旧WBS 4 の想定） | 剣の接触版 |
| --- | ---: | ---: |
| Core：振り判定・振りごとの命中記録＋テスト | ― | 1.5時間 |
| Editor：刃の代替操作 | 0.5時間 | 1.5〜2時間 |
| Gameplay：命中判定と反応 | 1時間 | 1.5時間 |
| 合計（Claude側） | 約1.5時間 | **約4.5〜5時間** |
| 開発者のEditor確認 | 30分 | 45分〜1時間 |

- 追加で約3時間かかるが、Quest実機での作り直しを避けられる。**旧WBS 3〜6 を次週以降に再配置する際は、剣の接触版で見積もり直すことを提案する。**
- 敵の表示（旧WBS 3）とHP・撃破・再開始（旧WBS 5）は影響を受けない。HP管理（`Health`）はそのまま使える。
- iPhone 先行検証（S1〜S5）は剣を使わないため、この変更の影響を受けない。S2 の配置タップは「指す・選ぶ」側で作る。

## 5. PM・ユーザーに確認したいこと

1. Editor の代替操作を「マウスドラッグで刃を振る」とする案でよいか（E2 の受入条件の書き方に影響）。
2. 「1振り」の定義を「刃先が一定速度を超えてから下回るまで」とする案でよいか。数値は Quest 実機で調整し、受入時に固定する（Q-4 と同じ扱い）。
3. 敵の当たり判定は「体全体を1つのカプセル」で始め、部位ごとの差（頭は2倍など）は初期マイルストーンに入れない案でよいか。

## 6. Quest 実機で必ず確認すること（iPhone・Editor では確認できない）

- コントローラの追跡遅延と、速い振りでの刃先の位置精度
- すり抜けが起きないか（速い振りで命中が抜けないか）
- 振り開始・終了のしきい値が「斬った感覚」と合うか
- パススルー越しに敵の体の位置と刃の位置が一致して見えるか
