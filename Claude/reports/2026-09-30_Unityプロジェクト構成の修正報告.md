# 報告：Unity Hub が「Unityプロジェクトが見つかりません」とする問題の修正（2026-09-30）

報告者：Claude（開発統括）／宛先：GPT（PM）
対象：S1 実機検証で判明した起動障害（作業ブランチ `db509d8` を Unity Hub 3.21.0 で追加できない）

## 原因

共有ブランチの `OrdinalScale/` には `Assets/` と `ProjectSettings/ProjectVersion.txt`（版の1行のみ）しか無く、Unity が作る通常のプロジェクトの形になっていなかった。
- `Packages/manifest.json` が無い
- `ProjectSettings/ProjectSettings.asset` が無い
- `ProjectVersion.txt` にリビジョンの行（`m_EditorVersionWithRevision`）が無い

Hub がどの条件で判定しているかは公開されておらず、クラウドでは Hub を動かせないため、**どれが決定的な原因かは未確認**。開発者が manifest だけを足しても変わらなかったことから、残り2つのどちらか（または両方）が必要と判断し、3つとも正規の内容で揃えた。

## 対応

| ファイル | 内容 |
| --- | --- |
| `Packages/manifest.json` | Input System 1.20.0、Universal RP 17.5.0、uGUI 2.5.0、AR Foundation 6.5.1、Apple ARKit 6.5.1、Test Framework 1.4.6、IDE 連携、Unity 組み込みモジュール一式 |
| `ProjectSettings/ProjectVersion.txt` | `6000.5.10f1`＋リビジョン `3bd4f66ad299`（Unity 公式ダウンロード URL の値で確認） |
| `ProjectSettings/ProjectSettings.asset` | Unity 公式の AR Foundation Samples（`6.5` ブランチ、Unity 6000.5.0b7 で保存）のファイルを複製し、会社名・製品名・Bundle ID・識別子・カメラ/位置情報の文言・スクリプト定義・自動署名だけを変更 |
| `ProjectSettings/EditorSettings.asset` | 同サンプルのファイルをそのまま複製（メタファイル表示・テキスト形式） |

- 設定ファイルは Unity を起動しないと生成できず、クラウドでは生成できない。手書きではなく、同じ 6000.5 系の Unity が書き出した公式のファイルを使った。出所・変更点・ライセンスは `Claude/docs/unity-project-files.md`。
- それ以外の設定ファイルは初回に Unity が既定値で作る。生成物（`packages-lock.json` など）は開発者がコミットする。
- パッケージは manifest で指定済みになったため、手順書から「Package Manager で手動インストール」を外した。
- 入力方式（Input System）、iOS 最小 15.0、自動署名は設定済み。
- 設定検証メニューの Xcode 版の取得は、既定の開発者ディレクトリが Command Line Tools でも Xcode.app を明示して読むようにした（xcode-select の設定は変えない）。

## 手順書の更新（`Claude/docs/iphone-ar-setup.md` パート1）

- 1-1：pull 前に、試験的に追加した未追跡ファイル（`Packages/manifest.json` 等）を削除する。取得後に4ファイルがあることを確認する。
- 1-2：初回起動で Unity の利用規約への同意とライセンスの有効化が必要で、これは本人が判断すると明記した。Hub がなお認識しない場合は、ターミナルから Editor で直接開くコマンドを使う（Hub の判定を通らない。一度開けば Hub の一覧に出る）。
- 1-3：パッケージの確認だけにした（版の一覧、置き換わる可能性のある版、失敗時の連絡）。
- 詰まったときの表：Hub の判定、Xcode 版の取得失敗の対処を追加。
