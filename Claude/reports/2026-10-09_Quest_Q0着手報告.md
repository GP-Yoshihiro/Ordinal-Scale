# 進捗報告：Quest 3／3S Q0（Unity／Android／XR の最小表示経路）（2026-10-09）

## 要点

- **方式を決めた**：Unity OpenXR Plugin **1.17.1**＋Unity OpenXR: Meta **2.5.1**＋既存の AR Foundation **6.5.1**。パススルーは `ARCameraManager` と OpenXR 機能「Meta Quest: Camera (Passthrough)」、コントローラは組み込みの `UnityEngine.XR` で読む。Meta XR Core SDK は使わない（理由は [quest-xr-setup.md](../docs/quest-xr-setup.md) 1章）。
- **実装した**：Quest 用シーンを作る Editor メニュー、Android／OpenXR 設定の適用・検証・APK ビルドのメニュー、正面2mの床への固定配置、剣の姿勢の境界 `ISwordPoseSource`（Quest のコントローラ用と Editor のマウス用）、Q1 へ渡す Core の `BladeSample`。iPhone のシーン・iOS 設定・ビルド対象一覧には触れていない。
- **このクラウド環境では Unity Editor と Android SDK が使えない**。そのため **Editor でのコンパイル・再生、Android ビルドはいずれも未確認**。開発者の Mac で約60〜90分の確認が必要（手順は quest-xr-setup.md 2章、記録欄は `Claude/reports/evidence/README.md` の Q0 記録表）。
- Quest 実機でのパススルー表示・コントローラ追跡・剣の操作感は**未確認**で、本報告のどの結果も実機合格を意味しない。

## 採用方式とリスク

| 項目 | 内容 |
| --- | --- |
| 追加パッケージ | `com.unity.xr.openxr` 1.17.1、`com.unity.xr.meta-openxr` 2.5.1（依存で `com.unity.xr.compositionlayers` 2.4.0 以上） |
| Android 設定 | IL2CPP／ARM64／最小 API 32（Android 12L。パススルー機能の要件）／Vulkan のみ |
| 有効にする OpenXR 機能 | Meta Quest Support、Oculus Touch と Meta Quest Touch Plus の入力プロファイル、Meta Quest: Session、Meta Quest: Camera (Passthrough)。平面・メッシュ等の部屋のスキャン系は使わない |
| リスク1 | `Packages/manifest.json` は Unity に書かせる方針のため、パッケージ未導入の現時点では Quest 用 Editor メニュー（2〜5）は現れない。メニュー1で追加後に現れる設計 |
| リスク2 | URP アセットは iPhone と共有。Meta 推奨（HDR・ポストプロセス無効）を今変えると iPhone 側の見た目に影響するため変更していない。パススルーが黒い・重い場合は Q4 で Quest 用の品質設定を分ける |
| リスク3 | 開発者の Mac では Meta Horizon Link（PC から Quest へ映す）が使えない。実機確認は APK を導入する方法になる |
| リスク4 | Unity が生成する設定（XR 設定アセット・ProjectSettings）は、メニュー実行後に開発者がコミットする必要がある |

## 実装内容

| 層 | 追加・変更 | 役割 |
| --- | --- | --- |
| Core | `Combat/BladeSample`（新規） | 刃の1フレーム分の観測値と刃先の速さ。追跡外・時刻が進まない区間は速さを出さない |
| Core | `PlacementMath.TryPointInFront`（追加） | 頭の位置と視線から正面 d m の床の点。真下を見ている間は決めない |
| Platform | `ISwordPoseSource`・`BladePose`（新規） | 剣の姿勢の境界。`ToSample()` で Core へ渡す |
| Platform | `XR/XRHeadSpatialProvider`・`XRControllerSwordPoseSource`・`XRRuntimeSwitch`（新規） | 頭部・床（追跡原点 Floor）・コントローラの刃。XR が無い Editor 再生ではマウス入力へ切り替える |
| Platform | `EditorSim/EditorSwordPoseSource`（新規）、`PlatformRig`（変更） | マウスの刃（C7 の最小版）。リグに `Sword` を追加し、有効な GameObject 上の実装を優先（iPhone シーンでは従来と同じ結果） |
| Gameplay | `Placement/FixedEnemyPlacement`、`Combat/SwordPoseDebugView`（新規） | 正面固定の配置。刃の表示と速さのログ（命中判定はしない） |
| Editor | `QuestPackageInstaller`（新規、常にコンパイル）、`Quest/QuestMRSetup`・`QuestSceneBuilder`・`EvidenceReport`（新規 asmdef） | パッケージ追加→設定適用→シーン作成→検証→APK ビルド。結果は `Claude/reports/evidence/` に保存 |

## 開発者に依頼すること（Q0 の残り。目安60〜90分）

1. Unity Hub で 6000.5.10f1 に Android Build Support（OpenJDK・SDK & NDK）を追加
2. ブランチ `claude/quest-q0-xr-path` を開き、メニュー `OrdinalScale > Quest MR` の 1〜5 を順に実行
3. 生成された `Packages/`・`ProjectSettings/`・`Assets/XR/`・`Quest_MR.unity`・`.meta`・証拠テキストをコミット（APK・キーストアは入れない）
4. コンパイルエラー・検証の NG・ビルド失敗があれば全文を Claude へ渡す（修正は Claude が行う）
5. iOS の検証メニュー（`OrdinalScale > iOS AR > 2`）で iPhone 経路の回帰が無いことを確認
