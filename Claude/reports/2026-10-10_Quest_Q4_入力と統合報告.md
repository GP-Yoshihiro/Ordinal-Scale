# 進捗報告：Quest Q4 コントローラの剣と、ヘッドセット内の「終了／再挑戦」（2026-10-10）

報告者：Claude（開発統括）／宛先：GPT（PM）
対象：`GPT/plans/2026-10-09_Quest戦闘開発.md` の Q4、仕様 E2・E4・Q-5（操作UIの方式の提案）
ブランチ：`claude/quest-q4-xr-input`（PR #14 の `5dacc12` の上）、下書き [PR #15](https://github.com/GP-Yoshihiro/Ordinal-Scale/pull/15)（基点は PR #14 のブランチ）。**PR #7・#8・#13・#14 の統合まで main へ入れない**

## 要点

- Quest の右コントローラの剣は、Q0 の `XRControllerSwordPoseSource` → Q1 の `SwordHitDetector`（1振り1命中）→ Q2・Q3 の戦闘という**既存の経路で通る**ことを確認した。Q4 での変更は不要（XR 実行時は `XRRuntimeSwitch` がコントローラ側を有効にし、`PlatformRig` がそれを使う）。
- 勝敗が決まると、**ヘッドセット内の正面1mに大きなパネル2枚（左＝終了、右＝再挑戦）**を出し、**剣先で指してトリガー**で選ぶ UI を実装した。Editor ではマウスのクリックで同じパネルを選べる。
- Core テストは **183件すべて成功**（クラウド。Q4 の追加は8件）。
- **このクラウド環境では Unity Editor・Android ビルド・シミュレータを使えない**。依頼の Unity テスト・シーン再生成・Validate・APK ビルド1回・静的検査は**未実施で、開発者の手順として下に記載**した。**Quest 実機の結果はすべて未確認**。
- パススルーを含む Android 設定（OpenXR・Meta Quest 機能・Vulkan・API 32・画面の向きの一時切り替え）は変更していない。iPhone 経路・Fab 原本・`GPT/` も変更していない。

## 操作方式の提案（Q-5「操作UIの方式はClaudeが提案する」）

**提案：剣先で指してトリガーで選ぶ、大きな2枚のパネル（最小構成）。**

| 項目 | 内容 | 理由 |
| --- | --- | --- |
| 指す | 右コントローラのグリップの向き（＝剣の向き）のレイ。指したパネルが明るくなり、先に白い点 | 剣をそのまま使うので持ち替えや別の操作が不要。実体の剣が見えているので狙いが分かる |
| 決定 | トリガーの押し始め | Quest のコントローラで最も確実に押せるボタン。剣を振る操作（トリガー不要）と重ならない |
| パネル | 決着時のプレイヤーの正面1m・目の0.2m下に固定。幅0.5m×高さ0.3m、中心間隔0.64m（1m 先で横約28°ずつ）。左＝灰「QUIT 終了」、右＝緑「RETRY 再挑戦」 | 頭を少し動かしても外れない大きさ。敵（1.2〜2m 先）より手前に出る。誤って終了しにくいよう終了は利き手と反対側（左） |
| 誤操作防止 | 表示から0.6秒は選べない（暗く表示）／表示前から押していたトリガーは数えない／1回選んだら表示し直すまで選ばない | 決着の瞬間に振っていた・押していた操作で勝手に決まらないようにする |
| Editor | 同じパネルをマウスのクリックで選べる。従来の画面ボタンも画面上寄りに残す | 実機なしで選択の流れを確かめるため |

代替案（今回は実装しない）：A ボタン＝再挑戦／B ボタン長押し＝終了。狙いが要らず最も確実だが、画面に操作の説明が要る。実機でレイが選びにくい場合に追加する（見積り0.5時間）。

## 技術判断

| 判断 | 内容 |
| --- | --- |
| 入力の抽象 | Quest の「指す・選ぶ」は既存の `IPointerInput` の実装 `XRControllerPointerInput` として追加（設計書どおり、戦闘の命中には使わない）。Editor は既存の `ScreenPointerInput` を Quest シーンの Editor 側に置く |
| 選択の規則は Core | `ChoicePanel.TryHit`（レイと長方形の交差）と `ChoiceSelector`（待ち時間・押し始め・1回だけ）を純C#にしてテスト。物理コライダーは使わない |
| 既存コードへの変更 | `BattleController` の Editor 用画面ボタンの位置を画面中央から上寄りへ移しただけ（3D パネルと重なり、1回のクリックで両方が反応するのを防ぐ）。勝敗・2択の動作は Q2・Q3 のまま |
| シミュレータ | Meta XR Simulator は Meta XR Core SDK が前提（Q0 で不採用）、XR Interaction Toolkit の Device Simulator は未導入。新しいパッケージを入れず、Editor の代替入力（マウスの剣・クリック）で流れを確認する手順にした |
