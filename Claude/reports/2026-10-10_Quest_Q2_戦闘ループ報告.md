## 要点

- 剣の**有効な命中だけ**で敵の HP を1ずつ減らし、**初期10回で撃破**する。9回・空振り・押し当て・同じ振りでの再接触では撃破しない。
- 撃破後は剣の判定を止めて**攻撃を無効化**し、敵を消して「VICTORY」と「終了」「再挑戦」の2択を出す（Editor の画面ボタン）。
- 再挑戦で**敵・HP・剣の判定を初期化**し、敵を正面に置き直す。終了は**実機で `Application.Quit`、Editor ではログで終了要求を確認**する。
- Core テストは **153件すべて成功**（クラウドで実行。うち Q2 の追加は17件）。**Q2 の Unity 側のコードは Unity Editor では未確認**。**Quest 実機での結果はすべて未確認**。
- iPhone の経路、`GPT/`、Fab の原本、APK は変更・公開していない。敵の移動・反撃・敗北（Q3）には手を付けていない。

## 技術判断

| 判断 | 内容 | 理由 |
| --- | --- | --- |
| 戦闘の規則を Core に置く | `BattleSession`：既存の `Core.Combat.Health` を保持し、`RegisterValidHit()` で1ダメージ。HP 0 で `Victory`。決着後だけ `Choose(Quit/Retry)` を受け付ける | ゲームルールは Core に書いてテストする（CLAUDE.md）。Unity なしで「9回では撃破しない」などを確かめられる |
| HP＝撃破に必要な有効命中数 | 1命中1ダメージ、初期 HP 10。Inspector の `Hits To Defeat` で変更可（受入時に固定して記録） | E3・Q-4「約10回」。設計書の初期設定（敵HP 10・1命中1ダメージ）どおり |
| 数えるのは Q1 の「命中」だけ | `SwordHitDetector` に出来事の通知 `Struck` を足し、`BattleController` は `Kind == Hit` のときだけ `RegisterValidHit` を呼ぶ | Q1 の判定（空振り・押し当て・触れ続け・再接触は命中にならない）をそのまま使い、Q2 側で規則を重複させない |
| 撃破後の攻撃無効は二重 | `SwordHitDetector` を無効にする（判定・HUD・色の更新が止まる）＋ `BattleSession` も撃破後の命中を無視 | 表示側の止め忘れがあっても HP は変わらない |
| 再挑戦の初期化 | `BattleSession`：HP 全快・状態・回数・ラウンド＋1。Gameplay：剣の判定と回数のリセット、判定の再開、`FixedEnemyPlacement.Reposition()` で敵をその時の正面に置き直す | E4「敵とHPを初期化」、依頼「剣判定を初期化」 |
| 終了 | `AppQuit`：`#if UNITY_EDITOR` ならログのみ（再生は止めない）、それ以外は `Application.Quit()`。要求は1度だけ通知 | E4「終了では実行アプリを閉じる。Editorでは終了要求を確認する」 |
| 表示 | `BattleView`：敵の頭上の HP バーと `VICTORY` の文字をワールド空間にプリミティブで作る。Editor では右上に状態、中央に2択ボタン（IMGUI） | アセットを増やさない。ワールド空間の表示はヘッドセット内でも見える想定（未確認） |
| 2択の操作 | Q2 では Editor の画面ボタン。ボタンの選択は次の `Update` で処理（IMGUI の途中で状態を変えない） | ヘッドセット内から選ぶ操作（コントローラのレイ＋トリガー）は Q4 の範囲。Q-5「操作UIの方式はClaudeが提案」→ Q4 でコントローラのレイで選ぶ方式を提案する |
