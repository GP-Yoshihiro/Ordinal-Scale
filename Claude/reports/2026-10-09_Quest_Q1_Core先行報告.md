# 進捗報告：Quest Q1 剣の命中判定（Core 側の先行実装）（2026-10-09）

報告者：Claude（開発統括）／宛先：GPT（PM）
対象：`GPT/plans/2026-10-09_Quest戦闘開発.md` の Q1、仕様 Q-2・E2（Claude 側の条件番号 C1〜C8：`Claude/docs/sword-input-design.md`）
ブランチ：`claude/quest-q1-sword-core`（Q0 の `claude/quest-q0-xr-path` の上）。**Q0 の Unity 検証前に main へ統合しない**

## 要点

- Quest 実機は今日から使えるが、開発者の Mac で Android Build Support を導入する空き容量が足りず（必要 9.07 GB／空き 4.57 GB）、Q0 の Editor コンパイル・APK ビルド・実機検証は止まっている。PR #7 は下書きのまま。
- その間に、Q1 の **Core 側の判定「振って敵の体に触れた時だけ、1振り1命中」を実装**した。入力は Q0 の `BladeSample`。空振り・ゆっくり押し当て・触れ続け・同じ振りでの再接触・別の振りでの再命中を区別する。
- Core テストは **112件すべて成功**（Q0 時点 59件＋今回 53件）。判定の規則を1つずつ外した版で対応するテストが失敗することも確かめた。
- **速度しきい値はすべて仮の値で、Unity・Quest では未確認**。Gameplay への接続（Unity 側）も未実装。HP・勝敗・敵 AI（Q2 以降）には手を付けていない。

## 実装した判定

命中は次の3つが同じフレームでそろったときだけ（設計書 3.2）。

| # | 条件 | 実装 | 対応する仕様 |
| --- | --- | --- | --- |
| 1 | 刃と敵の体の接触が「前フレームなし → 今フレームあり」に変わった | `SwordHitJudge`（敵ごとの前フレームの接触） | 触れ続けは命中しない（C3） |
| 2 | このフレームが振り中 | `SwingDetector`（刃先の速さ） | 振りの最中だけ（C1）、ゆっくり押し当ては不命中（C2） |
| 3 | この振りでまだその敵に当てていない | `SwordHitJudge`（振りごとの命中済み記録） | 1振り1命中（C5） |

| 部品 | 役割 |
| --- | --- |
| `SwordTuning` | 調整値。振り開始 1.5 m/s、終了 0.6 m/s が 80ms 継続、最短の振り 100ms、刃先の飛び 0.5 m/サンプル、サンプル間隔の上限 100ms、刃の半径 2cm。**すべて仮** |
| `SwingDetector` | 振りの開始・継続・終了。開始と終了の速さを分けて（ヒステリシス）切り返しで1振りが割れないようにする。追跡の途切れ・刃先の飛び・間隔の空きでは振りに数えない |
| `SwordContact`・`BodyCapsule` | 刃（手元→刃先の線分）と体（縦のカプセル1つ。部位差なし C6）の距離で接触を判定。前後フレームの刃を補間して調べ、速い振りのすり抜けを防ぐ |
| `SwordStrikeTracker` | 上をまとめる入口。毎フレーム `Step(BladeSample)`、各敵について `Resolve(敵ID, 体)` → 命中または不命中の理由（接触なし／触れ続け／振り中でない／この振りで命中済み） |

接触判定は当初 Gameplay（Unity の物理）に置く設計だったが、Unity なしでテストできるよう Core の幾何計算に移した。Gameplay 側は敵の位置から `BodyCapsule` を作って渡すだけになる。

## テスト（このクラウド環境で実行）

| 種類 | 件数 | 主な確認内容 |
| --- | ---: | --- |
| 場面テスト（90Hz の刃の動きを再生） | 13 | 速い振りで体を通過→1命中／ゆっくり押し当て→0／押し当てたまま速く動かす→0／体の中で動かし続ける→1／往復で再接触→1／止めてから次の振り→2／頭上の空振り→0／追跡の途切れ後に体の中で復帰→0／追跡の飛びで体の中へ→0／72Hz・約32 m/s のすり抜け→1／10回の振り→10命中／しきい値を変えると同じ動きが命中⇔押し当てに変わる／初期化 |
| 振り判定 | 13 | 開始・ヒステリシス・終了の継続時間・短い減速で割れない・最短時間・通し番号・追跡の途切れ・飛び・間隔の空き・同時刻サンプル・初期化 |
| 接触 | 15 | 線分どうしの距離（平行・交差・ねじれ・端点・点）、体全体が同じ当たり判定（胸・足元・頭頂・頭上）、刃の太さ、追跡外、掃引の有無 |
| 命中の規則 | 8 | 3条件それぞれ、1振りで2体、敵の置き直し |
| 調整値 | 4 | 既定値が設計書どおり、終了＞開始の拒否など |
| **今回の合計** | **53** | Core 全体 **112件成功** |

- 規則を外した版での失敗の確認：触れ続け判定なし→3件、振り中の条件なし→7件、1振り1命中なし→2件、掃引なし→2件、飛び判定なし→2件、ヒステリシスなし→1件、最短時間なし→1件が失敗。
- 整形チェック（`dotnet format whitespace … --verify-no-changes`）・`git diff --check`：問題なし。

### クラウドでの限界

- NuGet が組織の通信方針で遮断されているため、`dotnet test tools/CoreTests` そのものは実行できない。同じテストソースを NUnit の最小互換シムで実行した。開発者の環境で `dotnet test tools/CoreTests` または Unity の Test Runner（EditMode）で再実行して正式な結果とする。
- Unity Editor が無いので、Unity での Core のコンパイル（C# 9・`noEngineReferences`）は未確認。使った構文は既存の Core と同じ範囲に限っている。
- 場面テストの刃の動きは合成した理想的な軌跡。実際のコントローラの揺れ・遅延・追跡の乱れは含まない。

## 止まっている点（ユーザー判断）

Mac の空き容量不足で、Q0 以降の Unity 作業（Editor 確認・APK・実機）がすべて止まっている。Android Build Support だけで 9.07 GB、加えて Android 用の Library・IL2CPP のビルド中間ファイルで数 GB 使うため、**少なくとも 15 GB 程度の空き**を目安にしたい。選択肢：

- A. Mac の不要ファイルを整理して空きを作る
- B. Unity Hub の「インストール先」を外付け SSD に変えて Android モジュールを入れる
- C. 空き容量のある別の PC（Windows 可）で Q0 の手順を実行する

## 実機が必要な未確認事項（Q1 分）

- 振り開始・終了のしきい値が「斬った」「押し当てた」の感覚と合うか
- 速い振りで命中が抜けないか、追跡の途切れ・復帰で誤命中しないか
- 刃の長さ・向きと、パススルー越しの敵の体の位置が一致して見えるか
