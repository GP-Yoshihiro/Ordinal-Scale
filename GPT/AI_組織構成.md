# AI組織構成と意思決定（提案）

状態：**運用中の役割案**。ユーザーはClaudeを配下に置く進め方を求め、iPhone検証後はQuest開発へ進むよう指示した。個々の実装依頼は確定した要件・受入条件に結び付け、後続段階の未決事項は記録する。組織構成そのものへの明示的な最終承認は未確認。

| 役割 | 責任 | 決められること・報告先 |
| --- | --- | --- |
| 開発者（ユーザー） | 体験の目的、最初の完成範囲、期限、公開範囲、購入・費用、マイルストーンの最終判断 | 製品上の大きな選択を決める。GPTとClaudeの報告を受ける |
| GPT（PM・仕様責任者） | インタビュー、要件・受入条件、WBS、優先順位、進捗・負荷、意思決定の記録 | 確定済み範囲内のタスク順と作業量を調整し、Claudeに成果目標を渡す。範囲変更はユーザーに上げる |
| GPTの一時サブエージェント | 要件の抜け・矛盾の調査、仕様案の独立レビュー | GPTへ報告する。製品判断やClaudeへの直接指示は行わない |
| Claude（開発統括・技術責任者） | 実現性確認、技術設計、実装・統合、見積り、技術レビュー | 技術上の日常判断を行い、受入条件への影響・リスク・進捗をGPTへ報告する。配下の担当を指揮する |
| Claude配下：実装担当 | コードと実装の自己確認 | Claudeへ成果と懸念を報告する |
| Claude配下：アセット／UI担当 | 試作に必要な素材と視認性の検討、出典・利用条件の記録 | Claudeへ成果と懸念を報告する |
| Claude配下：QA担当 | 受入条件に対応した再現可能な確認、不具合の記録 | Claudeへ結果を報告し、受入判断用の証拠をGPTにも共有する |

## 仕事の受け渡し

1. GPTは、WBS番号、目的・対象要件・受入条件・優先度・制約を一つの依頼にまとめてClaudeへ渡し、週次計画に受け渡しを記録する。実装方法は指定しない。
2. Claudeは、実現性・見積り・技術的な選択・依存・リスクを返す。確定済みの範囲と作業枠に収まれば担当を割り当てて進め、超える場合はGPTが選択肢をユーザーに示す。実装中に製品上の判断が必要になった場合も同様とする。
3. Claudeは技術レビューと統合結果、QAの再現手順・結果をGPTへ報告する。GPTは受入条件と照合して進捗台帳を更新する。
4. 日常の実装・タスク順の調整は各責任者が進める。体験の範囲、期限の大幅変更、機材購入、公開・配布、マイルストーンの完了承認はユーザーが決める。

Claudeの報告・QAの再現手順と結果はClaude側に置き、GPTは読み取り専用で参照する。GPT側では該当WBS番号、受入条件、証拠の場所、未確認事項を週次計画へ記録する。GPTはClaude配下の担当へ直接指示しない。

2026-10-09時点の現行作業は[Quest戦闘開発計画](plans/2026-10-09_Quest戦闘開発.md)を参照する。iPhoneではモデル表示と待機・攻撃・待機復帰を確認したが、Questの実機受入は未実施。
