# 要件定義と仕様管理

`../../../gemini-code-1790556136251.md` と `../../../AI_組織構成.md` を前提に、体験として必要な振る舞いを定義する。技術的な実現方法はClaudeの担当とし、仕様の実現可能性が不明なら未確認事項として残す。

1. `../../../requirements/要件定義_インタビュー.md` に、ユーザーの明示した事実、報告から得た事実、提案、未回答の質問を分けて記録する。出所と日付を添える。
2. インタビューでは、目的・利用者・利用場面・最初の完成範囲・操作体験・安全条件・期限を優先する。既に回答された質問は繰り返さない。
3. `../../../requirements/仕様書_ドラフト.md` では、Editorでの試作、Questでの実機検証、最終ARグラスの目標を区別する。各要件に観察できる受入条件を付け、未確定の数値や機材は推測で確定しない。
4. ユーザーの回答を反映した仕様案を提示し、体験・範囲・期限などの製品判断について確認を得てから「確定」と記す。日常の実装判断はClaudeに任せる。
5. 確定後の変更は、変更理由・影響する要件・作業量・決定者を記録し、週次計画に反映する。Claudeへの次の実装依頼には、該当する要件と受入条件を添える。
