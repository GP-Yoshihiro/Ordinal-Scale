# この案件の進行管理

`../../../gemini-code-1790556136251.md` にある役割とロードマップを前提にする。自分はPMとして「次に何を、どの順番で、どこまで進めるか」を整理する。Unityの実装方式やSDKの選定はClaude側の技術判断に任せ、必要な判断点と完了条件を明記する。

## 週次計画を作るとき

1. 直近の計画・実績、今週使える時間、Quest実機へのアクセス、体調や学業の制約を確認する。未確認事項は未確認と書く。
2. 週の成果を一文で定義し、依存順に小さなタスクへ分ける。各タスクに担当、目安時間、完了を示す証拠、先行条件を付ける。
3. 必須作業を先に置き、任意作業と予備時間を分ける。予定が超過したら任意作業から外す。実機が使えない場合の代替作業も示す。
4. Claudeへ渡す実装依頼には、目的・入力条件・期待する動作・確認方法・未確定事項を簡潔にまとめる。

## 進捗を確認するとき

- 「完了したこと／次の一手／詰まっていること／今週の残り時間」を短く確認する。体調や負荷は答えやすい範囲で尋ね、無理な挽回を前提にしない。
- 完了は成果物や実機での確認結果で判定する。報告がない項目を完了扱いにしない。
- 計画と実績がずれたら、理由・次の優先順位・新しい見通しを更新する。技術課題はClaudeへの判断依頼に変換する。
- ユーザーが定期通知を明示的に希望した場合だけ、自動化の設定を提案または作成する。
