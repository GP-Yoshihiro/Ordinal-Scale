# GPTフォルダの運用

- ユーザーへの応答は、途中経過・質問・選択肢・最終報告を含め、すべて日本語で行う。
- この案件で編集・設定・生成するプロジェクトファイルは、この `GPT` フォルダ内に限定する。進捗と受入条件の確認に必要なClaude側の報告・成果物は読み取り専用で参照する。
- 役割とプロジェクトの前提は `gemini-code-1790556136251.md` を参照する。担当はPM・進行管理であり、実装はClaude側が担当する。
- 週次計画、WBS、進捗確認、作業負荷の相談では `.agents/skills/ordinal-pm/SKILL.md` を読み、その手順を使う。
- 要件インタビュー、仕様書、受入条件の作成・更新では `.agents/skills/ordinal-requirements/SKILL.md` を読む。
- AI間の責任と報告経路の提案は `AI_組織構成.md`、要件の回答と未決事項は `requirements/要件定義_インタビュー.md`、現在の仕様案は `requirements/仕様書_ドラフト.md` を参照する。
- 現行の計画と進捗は `2026-09-28_週次計画.md` に記録する。ユーザーの回答や実績が得られたら、推測で埋めずに更新する。

## 絶対遵守：時間・トークン節約

- GPT本体は仕様・優先順位・受入判断・PR最終確認だけを担当する。実装はClaude、Unity検証・レビュー・長いログ要約は役割を分けて担当へ委譲する。
- 小さな確認ごとに子エージェントを作らず、独立した作業をまとめる。同じファイルを並行編集しない。作業者には所有ファイル・停止条件・12行以内の報告形式を伝える。報告ファイルの指定がなければ新規作成せず、チャット内で要約する。
- 既存の `hq-section-orchestration`、`lean-token-workflow`、`minimal-read-edit` を利用可能なら適用し、足りないスキルだけGPT内に取得して出典を記録する。既にあるスキルは再取得しない。GPT外へのスキル導入は禁止する。ただし、ユーザーの明示的な個別許可を優先する。
- `rg` で対象箇所を絞り、長いログ・XML・ファイル全体・画像をGPT本体へ読み込まない。失敗行・件数・証拠パスだけを返す。
- 最小テストを一度実行し、変更や失敗がない限り繰り返さない。APKフルビルドは統合段階にまとめる。実機結果はEditorやAPKの成功から推定しない。
- 10月のユーザー作業枠は週約8時間。残時間やCodex残量を推測で書かず、必要なら実測値を確認する。
- 編集後は `git diff --check -- GPT/AGENTS.md` を実行し、差分要約だけを報告する。
